# 安装与容器运行环境

## 先查现状，再选安装方式

SSH 别名为 `huoshan`。先做必要的只读检查：系统/架构、实际 CPU/内存、磁盘、GPU/驱动、已安装版本、`uv`、容器运行用户及挂载。不要根据旧报告假定硬件仍相同，也不要输出整份环境变量或私有 Compose/env 文件。

当前已有软件、安装记录和模型可能可以复用。按用户目标检查可执行文件、许可证、模型是否到位，避免重复下载或重新建同一环境。若只要求安装，先准备可审查的安装方案；用户已明确授权开始后不重复确认。

仓库和安装器以官方发布或用户提供的文件为准。源仓库私有/需注册时，记录这一事实；已有合法的二进制安装器可作为独立安装路径，不得把二进制安装说成成功克隆了源码。按当前会话可用的联网技能核对官方依赖、许可证和模型用途。

## 目录与可复现记录

按实际需要创建目录，不必为没有的内容造空文件夹。典型布局：

```text
/root/EM-Agent-Tools/<tool>/
  README.md                 # 当前入口、用途、环境与记录位置
  installers/               # 安装器或原生扩展 wheel
  logs/                     # 安装日志、解析预览、下载校验
  docs/                     # 上游许可、安装说明、验收摘要
  validation/               # 每次真实测试的输入、日志、结果
  templates/                # 已验收的原生输入模板（如需要）
  pyproject.toml / uv.lock   # 需要 Python 时使用
  .venv/
```

运行时可安装到 `/opt/em-agent-tools/<tool>/...`，管理目录用说明或链接指向它。不要为了整理目录移动已有带绝对前缀的软件安装。所有权、符号链接和持久路径都属于安装记录的一部分。

记录版本、来源 URL/提交、安装器与模型 SHA-256、关键安装命令、锁文件和依赖检查结果。模型写入 manifest，注明适用元素/电荷/体系和单位。大文件下载中断后可以续传，但最终必须验证完整性，不能用部分文件继续计算。

## Python 与共享模型

- 默认采用每工具独立的 `pyproject.toml`、`uv.lock`、`.venv`，用锁定依赖重建，例如 `uv sync --frozen`。解释器先确认兼容性；不能只选“最新 Python”。
- 原生 wheel 的 Python ABI、系统架构、glibc/CUDA 与 Torch 版本共同决定环境。先查 wheel 标签、发行版依赖及目标容器，再决定是否需要独立兼容环境。
- 厂商自带 Conda/独立发行版可以保留。uv 用于可管理的附加 Python 环境，不必强行重打包厂商软件，也不要污染 base 或 Agent Server 依赖。
- 多工具共用的 MLIP 单独管理，例如 `/root/EM-Agent-Tools/mace-off23/`。某工具因 ABI 需要自己的兼容环境时，依赖可以隔离，权重仍共用同一份。
- 不直接复制或移动 `.venv` 后假定可用：解释器链接、入口 shebang 和本地 wheel 路径可能包含绝对路径。应在最终容器可见的前缀重新用锁文件安装，并检查解释器及动态库依赖。
- 下载慢时可选可用镜像/缓存；保留实际索引与依赖锁定信息，核对发行文件完整性，不用静默换版本来掩盖问题。

安装后做依赖一致性检查和最小真实计算。能 import、打印版本、通过 dry-run 都只是预检；它们不能证明受力、应力、SCF 或结构优化正常。

## 从宿主机进入容器

依据当前 `docker/EM-Agent.Dockerfile`、部署脚本和实际容器确定运行方式：

1. 原生程序和依赖安装到稳定路径，模型使用稳定的只读路径。
2. 经部署脚本管理只读挂载与必要环境，保持已有软件和持久卷。不要手工改线上容器里的安装路径作为最终方案。
3. 通过容器挂载把宿主机 `/root/...` 中的模型映射到容器可读的 `/opt/...` 等路径。不要为解决访问问题开放整个 `/root` 或使用全局 `chmod 777`。
4. 用镜像真正的运行用户验证完整调用。检查解释器符号链接目标、动态库、工作目录、临时目录及许可证访问。
5. 重依赖工具由它自己的解释器运行；科学服务模块本身避免在 import 时加载 Torch/ASE 等独立环境依赖，这样工具未挂载时仍能启动目录服务并显示“不可用”。

工具包装器使用明确的解释器和参数数组；必要时隔离 `PYTHONPATH`/用户 site。线程环境需包含实际使用的 OMP/MKL/OpenBLAS，并注意 MPI/PAL worker 与 BLAS 线程相乘的问题。不得仅凭宿主机 root 的 PATH 判定容器可用。
